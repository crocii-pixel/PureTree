# 시장 데이터

재수집이 불가능하거나 느린 데이터의 보관본입니다.
**앱이 읽는 경로는 아직 `%LOCALAPPDATA%\\QuantBot\\market_data` 입니다.**
여기는 사본이고, 원본이 갱신되면 다시 담아야 합니다.

## 들어 있는 것

| | 왜 |
|---|---|
| `market_cap/` | 일별 시가총액 상위 200 스냅샷 2013-04-28 ~. **CoinMarketCap 이 과거 엔드포인트를 닫으면 다시 못 만듭니다.** |
| `v1/BTC/1d`, `1h` | 글로벌 BTC 정본. 장세 판정이 읽습니다 |
| `v1/BTC/*/**.meta.json` | 체크섬·계보·행수 계약 |

## 안 들어 있는 것

| | 왜 |
|---|---|
| `v1/BTC/1m` (66MB) | 일봉 검증용 계보. Parquet 이라 git 압축이 안 듭니다(1.0:1). 재수집 가능하나 느립니다 |
| `tools/_cache/` (76MB) | 업비트·바이낸스에서 몇 분이면 재생성됩니다 |

## 시총 스냅샷은 시점 데이터가 아닙니다

`market_cap/observed_at.json` 을 보면 **4,869개 전부가 2026-08-26 ~ 08-27
26시간 안에 수집**됐습니다. 즉 이건 그날그날 캡처한 것이 아니라
**오늘 시점에서 본 과거의 재구성** 입니다.

"오늘의 상위 200 을 과거에 적용"보다는 확실히 낫지만 "그날 실제로 캡처한 것"
보다는 확실히 못합니다. 그때 존재했으나 이후 CMC 에서 제거된 코인이 빠졌을 수
있고(생존 편향의 뒷문), 공급량·시총이 소급 정정됐을 수 있습니다.

→ 오늘부터 **동시대 스냅샷을 별도로 쌓아** 12개월 뒤 재구성본과의 드리프트를
측정할 것.

## 압축

git 이 tar.gz 보다 낫습니다. 연속된 날짜 스냅샷이 서로 비슷해 델타 압축이
잘 듭니다.

```
원본 210 MB  →  tar.gz 47 MB (4.5:1)  →  git 21 MB (10:1)
```

그리고 매일 추가분이 통째 새 아카이브가 아니라 작은 델타 하나입니다.
**연도별 압축본으로 묶지 마십시오.**
