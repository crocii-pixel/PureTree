# 시장 데이터

**여기 있는 시총 스냅샷이 단일 원본입니다.** 앱이 이 경로를 먼저 봅니다
(`tools/market_cap._cache_root()`). 사본이 아니므로 따로 동기화할 것이 없습니다.

시세 아카이브(`v1`)는 **여기 없습니다.** 아래 "왜 갈랐나" 참조.

## 들어 있는 것

| | 왜 |
|---|---|
| `market_cap/` | 일별 시가총액 상위 200 스냅샷 2013-04-28 ~ 4,870개. **CoinMarketCap 이 과거 엔드포인트를 닫으면 다시 못 만듭니다.** |
| `market_cap/observed_at.json` | 각 스냅샷을 언제 받았는지. 파일 mtime 에서 건진 것이라 복사 한 번이면 사라졌을 정보입니다 |

## 왜 시세 아카이브는 안 옮겼나

파생 사슬 때문입니다. `v1/BTC/1h` 와 `1d` 의 manifest 가 둘 다
`derived_from: "1m"` 이고, `ensure_global_btc_current()` 는 1분봉이 없으면
**예외가 아니라 `False` 를 조용히 돌려줍니다.** 그러면 장세 판정이 과거
데이터에 멈춘 채 계속 돕니다.

그리고 1분봉은 66MB 에 Parquet 이라 git 압축이 안 듭니다(1.0:1).

```
시총 스냅샷   재수집 불가능   파생 사슬 없음   → 리포를 단일 원본으로
BTC v1        재수집 가능     1h·1d 가 1m 파생 → %LOCALAPPDATA% 유지
```

기준은 **"다시 만들 수 있는가"** 입니다. BTC 아카이브는
`BitstampBTCArchive.run()` 으로 재생성됩니다. 느리지만 가능합니다.

### 백테스트만 놓고 보면 1시간봉으로 충분합니다 (2026-08-28 측정)

파이프라인과 별개로, **검증과 백테스트에는 1분봉이 필요 없습니다.**

```
1시간봉 → 일봉 재생성   5,487일 전부  최대 상대오차 0.00e+00  불일치 0일
1분봉   → 일봉 재생성   5,487일 전부  최대 상대오차 0.00e+00  불일치 0일
```

`verify(deep=True)` 가 하던 "일봉을 재생성해 대조"가 1시간봉으로 똑같이 됩니다.

장중 순서 모호성도 재 봤습니다. 하루 안에서 급락 임계선(시가 −3.5 ATR)과
K 돌파 목표가가 **둘 다** 닿으면 일봉으로는 순서를 알 수 없어 보수적으로
하락 우선을 가정해 왔는데, BTC 기준 **3,258일 중 0일**이었습니다.

남는 차이는 **한 시간 안에서 일어났다 되돌아온 움직임**뿐입니다. 저가·고가는
보존되므로 "닿았는가"는 정확하고 "언제·얼마나 오래"만 흐려집니다. 이 전략은
레벨에 반응하지 지속시간에 반응하지 않으니 해당 없습니다.

→ **그래도 1분봉은 지우지 마십시오.** 백테스트에는 필요 없지만 갱신
파이프라인의 기반입니다.

## 안 들어 있는 것

| `tools/_cache/` (76MB) | 업비트·바이낸스에서 몇 분이면 재생성됩니다 |

## 시총 스냅샷은 시점 데이터가 아닙니다

`observed_at.json` 을 보면 **4,869개 전부가 2026-08-26 ~ 08-27 26시간 안에
수집**됐습니다. 그날그날 캡처한 것이 아니라 **오늘 시점에서 본 과거의
재구성**입니다.

"오늘의 상위 200 을 과거에 적용"보다는 확실히 낫지만 "그날 실제로 캡처한 것"
보다는 확실히 못합니다. 그때 존재했으나 이후 CMC 에서 제거된 코인이 빠졌을 수
있고(생존 편향의 뒷문), 공급량·시총이 소급 정정됐을 수 있습니다.

→ 오늘부터 **동시대 스냅샷을 별도로 쌓아** 12개월 뒤 재구성본과의 드리프트를
측정할 것.

## 압축

git 이 tar.gz 보다 낫습니다. 연속된 날짜 스냅샷이 서로 비슷해 델타 압축이 듭니다.

```
원본 210 MB  →  연도별 tar.gz 47 MB (4.5:1)  →  git 46.6 MB (4.6:1)
```

비슷해 보이지만 **매일 추가분이 통째 새 아카이브가 아니라 작은 델타 하나**라
히스토리가 훨씬 덜 자랍니다. **연도별 압축본으로 묶지 마십시오.**
